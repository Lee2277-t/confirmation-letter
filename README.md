# 函证助手 v1.0

从往来余额表里挑出要函证的单位，生成**函证控制表**（Excel）和**询证函**（可打印）。

单页 HTML，解压后双击 `index.html` 就能用。不用装、不用联网，**文件只在浏览器里读，不上传任何地方**。

> 仓库：<https://github.com/Lee2277-t/confirmation-letter>
> 直接下载：<https://github.com/Lee2277-t/confirmation-letter/releases/latest>

---

## 它解决什么

函证这个环节，实习生最常做的事是：从客户的往来明细里挑出要发函的单位 → 一个个做成询证函 → 再登记发函回函。

手工做的问题不是慢，是**容易漏和容易错**：

- 挑的时候凭感觉，事后说不清为什么挑这几家
- 同一家客户挂了三个科目，函却只发了其中一个的金额
- 台账和函对不上，回函回来了找不到对应哪一户

这个工具把「挑」和「出函」两步固定下来，留下的痕迹能写进底稿。

## 怎么用

### 1. 上传往来余额表

需要**一列单位名称**（客户/供应商）和**一列期末余额**。科目、账号有的话会一起带出来，写进函里。

能认的列名包括：单位名称 / 客户名称 / 供应商名称 / 往来单位 / 户名、期末余额 / 余额 / 金额。表头在前 20 行内都能找到。

> 没有文件可以先点「用示例数据试一下」，示例是虚构的。

### 2. 选样

| 口径 | 说明 |
|---|---|
| 大额全要，其余随机补足 | **推荐**。超过门槛的全部发函，剩下的随机补齐 |
| 只要超过金额的 | 纯阈值 |
| 纯随机抽 | 不看金额 |
| 全部都要 | 小额也要函 |

**随机种子**：同一个种子抽出来的是同一批。写进工作底稿，复核的人能重跑出一样的结果——这比"我是随机抽的"有用得多。

### 3. 核对后生成

列表里每一户都能取消勾选（比如已经结清、或者对方是小额关联方）。

- **函证控制表（Excel）**：序号、被函证单位、科目、账面余额、函证金额、选样方式，后面留了发函日期、回函日期、回函金额、差异、差异说明五列
- **询证函（打印版）**：一户一页的 HTML，浏览器打开后 Ctrl+P 打印，或另存为 PDF

## 它不做什么

说清楚边界，比吹功能有用：

- **回函登记和差异调节要你自己填**。控制表里那几列是空的，不预填假数据。
- **银行询证函有固定格式**（含银行存款、借款、担保、票据等十四项），这个工具出的是**企业往来款项**的通用格式，不替代银行询证函模板。
- 不做函证程序设计（发多少、发哪些），那是项目组的判断；它只把你定的口径执行到位。
- 不做替代程序。

## 几个设计上的取舍

**金额一律按分算。** 内部用整数分，显示才转成元，不会出现 `0.1 + 0.2 = 0.30000000000000004`。

**同名单位合并。** 一家客户挂应收账款和预收账款，函是发给这个单位的，金额就该合在一起。科目会在函里列全。

**读不出的行不丢。** 金额是「待核实」这种文字、或者有金额没单位名称的行，会单独报出来并说明原因，不会悄悄跳过——悄悄跳过的结果是底稿少一笔钱，而没人知道。

**`12,34` 这种不认。** 千分位只认「每三位一组」。`12,34` 到底是 1234 还是 12.34，猜错就是一笔钱的差错，宁可不认，报出来让人看。

**合计行自动跳过**，不当成一家单位。跳过的行会在提示里写清原表行号和金额，不无声丢弃。

## 数据安全

所有处理都在你自己的浏览器里完成。没有后端，没有埋点，没有上传。

**但请注意**：工具会生成**真实的询证函文件**，里面有客户的单位名称和金额。这些文件按你所在单位的保密要求管理，不要随手发到不该去的地方。

## 只认这三种表（重要）

被 16 轮独立复核打磨下来，这个工具**故意把范围收窄了**。只认下面三种，其余一律拒绝并说明原因：

| # | 形态 | 例子 |
|---|---|---|
| 1 | 单位名称 + 期末余额 | `客户名称` + `期末余额` |
| 2 | 单位名称 + 借方余额 + 贷方余额 | 按 借 − 贷 合成净额 |
| 3 | 单位名称 + 科目 + 期末余额 | 一家单位占多行，名称可合并或只写首行 |

名字列认：单位名称 / 客户名称 / 供应商名称 / 往来单位 / 户名 / 核算项目（金蝶）。

**会拒绝的**（界面上会写清楚为什么）：

- 科目余额表（科目编码 + 科目名称，没有往来单位）——函证对象是往来单位，不是科目
- 流水账（有日期/凭证/摘要，金额列是「金额」或借贷两栏）——每行是一笔交易，不是每个单位的余额
- 逐笔台账（有摘要/日期，余额列是「余额」）——那个余额是逐笔累计的，按单位相加会翻倍
- 只有期初余额，或只有本期发生额——函证要的是截止日余额
- 多列「…余额」并列（应收账款余额 / 预收账款余额 / 其他应收余额）——分不清该函哪一列
- 表里任何地方出现「万元 / 千元 / 亿元 / 百万元」（含工作表名）——**工具只认元**

最后一条是刻意的：自动换算猜错就是一万倍的差错，宁可让你在 Excel 里乘一次。

## 已知限制

- **金额单位只认元。** 万元表请先乘 10000 再导入。
- **一次处理一个文件的一张表。** 多张可用表时会给下拉框让你选，并在识别结果里提示「还有 N 张表也能用」。
- **同名不自动认定。** 两家公司同名但编码不同时，工具会停下来让你确认，不会把两家的钱写进一封函。
- **拿不准就整表拒绝。** 比如「没有单位名称、金额又对不上上面合计」的行，工具不猜是谁的钱，直接停下来告诉你第几行有问题。
- 询证函是简体中文、A4 的通用版式。要套事务所模板的话，改 `core.js` 里的 `letterHTML`。
- 两级表头支持的是「上一行写期间、下一行写借贷」这种常见排法；更复杂的多层合并可能认不出来，认不出会说"找不到可认的表"。

## 为什么这么保守

函证是要盖章寄出去的。一张函发错，错的不只是数字，是底稿、是回函、是复核。

所以这个工具在**拿不准的时候一律停下**：宁可让你手工整理一次表，也不肯给你一个看起来对、其实是错的结果。

16 轮复核里，被修掉的绝大多数问题都是"某种写法没认出来导致算错"。现在的做法是：不追求"什么表都能认"，只保证**认得出的一定对，认不出的明说**。
